# 문서 모델 — 레거시 텍스트 에디터와 수동 저장

> 상태: **A~E 적용됨 · F 보류** · 대상: `sagak-core` + `sagak-ui` + `apps/editor`
> 관련: [`app-or-library.md`](./app-or-library.md), [`toolbar-options.md`](./toolbar-options.md)

## 요약 (결론 먼저)

1. 제품의 모양을 **레거시 텍스트 에디터**로 잡습니다 — 새로 만들기 · 열기 ·
   저장 · 다른 이름으로 저장. 자동 저장은 **나중에 고도화**합니다.
2. 지금 저장소에는 **문서라는 개념이 아예 없습니다.** 이름 없는 버퍼 하나이고,
   앱은 67줄짜리 셸입니다. 그래서 이건 기능 추가가 아니라 **제품 방향**입니다.
3. 저장 자리는 **OPFS**(`navigator.storage.getDirectory()`)입니다. 주요 브라우저
   전부에서 되고, 권한 대화상자가 없습니다. 사용자의 진짜 파일을 다루는
   `showSaveFilePicker` 는 **Chromium 전용**이라 기본으로 삼을 수 없습니다.
4. 필요한 조각을 전부 굴려 봤습니다 — 이름 바꾸기(`move()`), 수정시각 정렬,
   488KB 왕복 **쓰기 6.3ms / 읽기 3.4ms**. 막히는 곳이 없습니다.
5. **걸리는 것은 하나입니다: `persist()` 가 `false` 를 돌려줍니다.** 텍스트
   에디터의 문서가 저장 공간 부족 시 브라우저에 지워질 수 있다는 뜻이라,
   이 설계에서 제일 먼저 답해야 할 문제입니다 (§4).
6. **A~E 는 적용했습니다** (`#43`). **F(자동 저장)는 보류**이고, 시작하기 전에
   답해야 할 다섯 가지를 §8 에 적어 두었습니다 — 어려운 것은 구현이 아니라
   판단입니다.

## 1. 왜 자동 저장이 아니라 수동 저장인가

자동 저장은 이번에 걷어냈습니다. 이유는 두 가지였고, 그 둘이 이 설계의 근거가
됩니다.

| 문제 | 실측 |
| --- | --- |
| **수다스러웠다** | 사람처럼 3번 치고 쉬면 표시가 **6번** 바뀝니다 |
| **정체가 없었다** | 어디에 저장되는지가 없어 "저장됨" 이 무슨 뜻인지 모호 |

두 번째가 본질입니다. **저장할 대상이 없는데 저장 상태만 있었습니다.** 문서에
이름과 자리가 생기면 "저장" 이 비로소 뜻을 갖고, 상태는 2초마다 바뀌는 토스트가
아니라 **제목 옆의 점 하나**가 됩니다.

```
● 메모.html        ← 저장 안 됨
  메모.html        ← 저장됨
```

깜빡임 문제가 고쳐지는 게 아니라 **생길 자리가 없어집니다.**

## 2. 웹에는 파일 시스템이 둘 있습니다

| | **OPFS** | File System Access |
| --- | --- | --- |
| 진입점 | `navigator.storage.getDirectory()` | `showSaveFilePicker()` 등 |
| 무엇 | 오리진 전용 **가상 FS**, 사용자에게 안 보임 | 사용자의 **진짜 파일** |
| Chrome · Edge | ✅ | ✅ |
| **Safari** | ✅ (15.2+) | ❌ |
| **Firefox** | ✅ (111+) | ❌ |
| 권한 대화상자 | 없음 | 매번 |

**기본은 OPFS 입니다.** 진짜 파일 쪽을 기본으로 삼으면 Safari·Firefox 에서 저장
자체가 안 됩니다. 진짜 파일은 **덤**으로만 답니다 (§6).

---

## 3. 필요한 조각을 굴려 봤습니다

전부 이 저장소의 브라우저 환경에서 실제로 실행한 결과입니다.

| 필요한 것 | 어떻게 | 결과 |
| --- | --- | --- |
| 만들기 · 쓰기 · 읽기 | `getFileHandle({create:true})` → `createWritable()` | 됩니다 |
| 목록 | `root.entries()` | 됩니다 |
| 삭제 | `root.removeEntry(name)` | 됩니다 |
| **이름 바꾸기** | `handle.move('새이름.html')` | 됩니다 · 내용 유지 |
| **최근 문서 정렬** | `File.lastModified` | 됩니다 · 파일마다 값이 다름 |
| 큰 문서 | 488KB | **쓰기 6.3ms · 읽기 3.4ms** · 왕복 일치 |
| 할당량 | `storage.estimate()` | **0.90GB** |

성능은 문제가 아닙니다. 488KB 는 원고지 수천 장이고, 왕복이 10ms 안입니다.

### 3.1 `move()` 는 확인이 더 필요합니다

이름 바꾸기를 `move()` 하나로 끝낸 것은 **이 브라우저(Chromium)에서 잰
결과**입니다. `move()` 는 OPFS 전체에 있는 것이 아닐 수 있습니다. Safari·Firefox
에서 없으면 **읽어서 새 이름으로 쓰고 지우기**로 대체해야 합니다 — 동작은
같지만 큰 문서에서 두 배 비용입니다.

**단계 A 에서 대체 경로를 함께 넣고, 두 브라우저에서 재는 것을 조건으로
답니다.**

## 4. 제일 먼저 답할 문제 — 문서가 지워질 수 있습니다

```
persisted(): false
persist() 요청 결과: false
```

OPFS 는 기본적으로 **"best-effort"** 저장소입니다. 저장 공간이 모자라면 브라우저가
지울 수 있습니다. 텍스트 에디터가 **사용자 문서를 잃을 수 있다**는 것은 그냥
넘길 문제가 아닙니다.

`persist()` 가 `false` 인 것은 이 헤드리스 환경에 사용자 참여 이력이 없어서일
수 있습니다 — 실제 브라우저에서는 방문 이력·북마크·PWA 설치 같은 신호가 있으면
허용되는 것이 보통입니다. **하지만 그건 아직 안 재 봤습니다.** 실제 브라우저에서
재는 것이 단계 A 의 첫 항목입니다.

어느 쪽이든 설계는 이걸 전제해야 합니다.

| 대비 | 내용 |
| --- | --- |
| 요청은 한다 | 첫 저장 때 `persist()` 를 부르고, 거절이면 조용히 넘어갑니다 |
| **내보내기를 붙여 둔다** | 이미 있는 기능입니다 — `html`/`markdown`/`text` 다운로드 |
| 지워졌을 때 정직하게 | 목록이 비면 "저장 공간이 회수됐을 수 있습니다" 를 말합니다 |
| Chromium 이면 진짜 파일 | §6 |

**"브라우저에 보관합니다" 를 사용자에게 숨기지 않는 것**이 이 설계의 태도입니다.

## 5. 모양

### 5.1 층

```
apps/editor      메뉴(새로 만들기·열기·저장·다른 이름으로) · 제목 · 문서 목록
     ↑
sagak-ui         useDocument() — 현재 문서, 더러움, 저장/열기 명령
     ↑
sagak-core       DocumentStore — OPFS 위의 목록/읽기/쓰기/이름바꾸기/삭제
```

`DocumentStore` 를 core 에 두는 이유는 **뷰를 모르기 때문**입니다
([`app-or-library.md`](./app-or-library.md) §4 의 경계와 같습니다). OPFS 는
렌더러와 무관합니다.

### 5.2 상태

문서 하나에 대해 알아야 하는 것은 셋뿐입니다.

| | 뜻 |
| --- | --- |
| `name` | `메모.html` · 없으면 `Untitled` |
| `saved` | 마지막으로 저장한 내용 |
| `dirty` | 지금 내용 ≠ `saved` |

`dirty` 를 **따로 들고 있지 않고 비교로 얻습니다.** 자동 저장에서 `isDirty`
플래그가 여기저기서 갱신되며 어긋났던 것과 반대로 갑니다.

### 5.3 하지 않는 것

닫을 때 경고(`beforeunload`)는 **답니다** — 레거시 에디터의 계약입니다.
다만 자동 저장을 안 하므로 그 경고가 마지막 방어선입니다.

## 6. 진짜 파일은 덤으로

Chromium 이면 `showSaveFilePicker()` 로 **내 컴퓨터에 저장**을 함께 줍니다.
없는 브라우저에서는 그 메뉴가 안 나옵니다 —
[`toolbar-options.md`](./toolbar-options.md) 의 규칙과 같습니다: **설치되지 않은
기능은 내놓지 않는다.**

이건 OPFS 를 대체하는 것이 아니라 **밖으로 꺼내는 길**이고, §4 의 대비이기도
합니다.

## 7. 단계

각 단계는 따로 머지할 수 있습니다.

| 단계 | | 상태 |
| ---- | ------------------------ | ----------- |
| A    | `DocumentStore` (core)   | 적용 `#43`  |
| B    | `useDocument()` (ui)     | 적용 `#43`  |
| C    | 메뉴와 제목 (ui)         | 적용 `#43`  |
| D    | 문서 목록                | 적용 `#43`  |
| E    | 내보내기 · 진짜 파일     | 적용 `#43`  |
| F    | 자동 저장 다시           | **보류** §8 |

### A. `DocumentStore` (core) — 화면 변화 없음

- OPFS 위의 목록/읽기/쓰기/이름바꾸기/삭제
- `move()` 없는 브라우저용 대체 경로 (§3.1)
- ~~**먼저 잴 것**: `persist()` 가 허용되는가~~ → 쟀습니다. 자동화 프로필에서는
  알림 권한을 줘도 `false` 였지만 **껐다 켜도 문서는 남았습니다**(§4). 사용자
  참여가 쌓인 실제 브라우저는 여전히 미측정
- **테스트**: 왕복 일치 · 목록 정렬 · 이름 충돌 · 큰 문서
- **대조군**: 쓰기를 건너뛰면 왕복 테스트가 깨져야 합니다

### B. `useDocument()` (ui) — 화면 변화 없음

- 현재 문서 · `dirty` · 저장/열기/새로 만들기
- `dirty` 는 **비교로** 얻습니다 (§5.2)
- **대조군**: `dirty` 를 항상 `false` 로 두면 저장 표시 테스트가 깨져야 합니다

### C. 메뉴와 제목 (app)

- 새로 만들기 · 열기 · 저장(⌘S) · 다른 이름으로 저장
- 제목 옆 점 하나로 `dirty` 표시 (§1)
- `beforeunload` 경고
- **테스트**: 저장 → 다시 열기 → 같은 내용

### D. 문서 목록

- 최근 수정 순 (§3 에서 `lastModified` 로 되는 것을 확인)
- 이름 바꾸기 · 삭제

### E. 내보내기·진짜 파일 (§6)

### F. 자동 저장 다시 — **고도화** (아직 안 함)

문서 정체가 생긴 **뒤에** 붙입니다. 그때는 예전 문제가 안 생깁니다 — 저장 대상이
분명하고, 상태가 제목에 붙으므로 토스트가 깜빡일 자리가 없습니다.

A~E 를 마친 시점에 **무엇이 어려운지**를 §8 에 적어 두었습니다. 어려운 것은
구현이 아니라 판단이고, 지금 재 둔 것들이 신선할 때 남겨야 나중에 꺼낼 때
처음부터 다시 재지 않습니다.

## 8. F단계를 시작하기 전에 답할 것

### 8.1 F 는 저장 수단이 아니라 **크래시 그물**입니다

이것이 전제이고, 여기서 나머지가 따라옵니다.

그러면 자동 저장은 **문서 파일에 쓰면 안 됩니다.** 사용자가 저장하지 않은 내용을
이름 붙은 파일에 몰래 넣는 셈이 되고, "저장은 내가 시킬 때만" 이라는 이 문서
전체의 계약이 그 자리에서 깨집니다.

별도 기록으로 가야 합니다. 자리는 확인해 뒀습니다 — **OPFS 에 하위 디렉터리가
되고**, `DocumentStore.list()` 가 `kind === 'file'` 만 세므로 `.recovery/` 를
만들어도 **문서 목록에 안 섞입니다.**

```
/                문서
  메모.html
/.recovery/      복구 기록 — 목록에 안 보입니다
  메모.html
```

**A단계를 고칠 필요가 없습니다.**

### 8.2 돌 때는 아무 말도 하면 안 됩니다

자동 저장을 내린 이유가 수다스러움이었습니다 — 사람처럼 3번 치고 쉬면 표시가
6번 바뀌었습니다.

그러므로 F 는 **저장하는 동안 아무 표시도 하지 않고**, 오직 **복원할 때만** 입을
엽니다. 이건 취향이 아니라 제약입니다. `Saving…` 같은 것을 다시 넣으면 내렸던
이유가 그대로 돌아옵니다.

제목 옆 점은 이미 있고, 그건 **저장 여부**를 말하지 자동 저장을 말하지 않습니다.
둘을 섞으면 점의 뜻이 흐려집니다.

### 8.3 복원은 물어봐야 합니다

레퍼런스가 갈리는 자리이고, 이 제품은 **묻는 쪽**입니다.

| 무엇 | 하는 일 |
| --- | --- |
| WordPress | "브라우저 백업이 아래 버전과 다릅니다" + `Restore the backup` |
| TinyMCE | `Restore last draft` 메뉴 — 누를 때만 |
| 예전 sagak | `restoreOnInit` 으로 **조용히 덮어씀** |

셋째가 이번에 문제가 된 그 동작입니다. 문서를 열면 **내가 저장한 것이 열려야**
하고, 더 새로운 복구본이 있으면 그것은 **제안**이어야 합니다.

### 8.4 제일 어려운 것 — `Untitled`

이름 없는 문서에서 쓰다가 탭을 닫으면 **복구본을 붙일 문서가 없습니다.**

그런데 자동 저장의 값이 가장 큰 경우가 정확히 이것입니다 — 아무것도 저장되지
않은 상태니까요. **정체가 없어서 못 붙이는데 값은 제일 큰** 자리라, 여기서 답이
갈립니다.

| 고르는 것 | 결과 |
| --- | --- |
| Untitled 도 남긴다 | 다음에 열 때 "이름 없는 초안이 있습니다". 여러 개면? |
| 안 남긴다 | 단순해지지만 **F 의 값이 절반으로 줄어듭니다** |

이 질문에 먼저 답하지 않으면 나머지 설계가 흔들립니다.

### 8.5 `beforeunload` 경고와 겹칩니다

C단계에서 붙인 경고가 지금은 마지막 방어선입니다. F 가 생기면 사용자에게
**"안전합니다" 와 "잃을 수 있습니다" 를 동시에** 말하게 됩니다.

OPFS 는 best-effort 라(§4) 복구본도 절대적이지 않으므로 경고는 남기는 쪽이 맞아
보입니다. 다만 그렇게 정하면 **F 가 무엇을 더 주는가**를 다시 답해야 합니다 —
"경고를 무시하고 닫았을 때" 와 "브라우저가 죽었을 때" 뿐입니다. 그 둘을 위해
얼마나 만들 것인지가 F 의 크기를 정합니다.

### 8.6 기존 플러그인은 재사용이 아니라 대체

`auto-save-plugin` 은 아직 core 에 있고 테스트도 살아 있지만 **문서를
모릅니다** — `storageKey` 하나에 씁니다. 문서마다 복구본이 필요한 이 설계와는
다른 물건이라, 고쳐 쓰기보다 새로 만들고 예전 것을 걷어내는 쪽이 깨끗해
보입니다.

걷어낼 때 딸려 오는 것: `AutoSaveIndicator`(`Toolbar` 에서 기본 꺼짐),
`useAutoSave`, `AUTO_SAVE_*` 이벤트 4종, 관련 테스트 21개.

## 10. 열린 질문 — 답이 바뀌면 설계도 바뀝니다

1. **실제 브라우저에서 `persist()` 가 허용되는가?** (§4)
   거절이 기본이라면 "브라우저에 보관" 만으로는 텍스트 에디터를 이룰 수 없고,
   §6 의 진짜 파일이 덤이 아니라 **주 경로**가 되어야 합니다. **이것부터
   재야 합니다.**

2. **`move()` 가 Safari·Firefox 에 있는가?** (§3.1)
   없으면 대체 경로로 갑니다. 동작은 같고 비용만 다릅니다.

3. **문서 형식을 무엇으로 저장하는가?**
   지금 에디터의 내용은 HTML 입니다. 그대로 `.html` 로 두면 밖에서도 열립니다.
   **지금 기울기**: `.html`. 새 형식을 만들지 않는 쪽.

4. **기존 사용자의 `sagak-editor-autosave` 는?**
   자동 저장을 끄면서 남겨 둔 값입니다. 문서 모델이 생기면 **첫 실행에서 문서
   하나로 옮겨 줄** 수 있습니다. 지금은 남의 데이터라 손대지 않았습니다.
