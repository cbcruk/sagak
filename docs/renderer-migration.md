# 렌더러 이주 기록 — Preact → 커스텀 엘리먼트 → Svelte

> 상태: **완료** · 대상: `packages/ui`, `apps/editor`
> 이전 이름: `nanotags-migration.md` (계획서였고, 실제로 간 길과 이름이
> 갈렸습니다)
> 관련: [`app-or-library.md`](./app-or-library.md),
> [`kinu-evaluation.md`](./kinu-evaluation.md),
> [`selection-state.md`](./selection-state.md)

## 요약 (결론 먼저)

1. **끝났습니다.** 렌더러가 Svelte 하나입니다. `preact` ·
   `@preact/signals` · `lucide-preact` · `kinu` · `nanotags` 가 저장소에서
   사라졌습니다.
2. **번들 이득은 예측과 달랐습니다.** 계획서는 JS 에서 gzip 약 5 kB 를
   기대했는데 실제로는 **0.1 kB** 입니다. 대신 아무도 안 세던 **CSS 가
   절반 아래**로 줄었습니다 (§2). 예측이 본 것과 실제로 값이 나온 곳이
   달랐습니다.
3. **골짜기는 예측대로였습니다.** 두 렌더러가 함께 실리던 이주 중간에
   번들이 271.7 kB 까지 부풀었다가 제자리로 돌아왔습니다.
4. **이주가 찾아낸 것이 이주가 바꾼 것보다 큽니다.** 사보타주 68번 중
   **27번이 아무 검사도 안 걸렸고**, 그 구멍을 메우며 검사가 늘었습니다.
   그중 하나는 검사 구멍이 아니라 **제품 결함**이었습니다 (§4).
5. **살아남은 것은 렌더러를 안 보던 코드입니다.** `subscribeToSelection` ·
   `icon()` · `getCurrentAlignment` 는 렌더러를 **네 번** 갈아타는 동안
   한 번도 안 바뀌었습니다 (§5).

## 1. 어떻게 갔나

계획서는 Preact → nanotags(커스텀 엘리먼트) 한 번을 그렸습니다. 실제로는
중간에 방향을 한 번 틀어 **두 번** 갈아탔습니다.

| 구간 | 무엇 | 왜 |
| --- | --- | --- |
| Preact → nanotags | 툴바 컨트롤 12개 | 계획서 1단계 |
| **방향 전환** | — | 남은 일이 다이얼로그 위주라는 것이 드러남 |
| Preact → Svelte | 다이얼로그·메뉴·앱·하네스 | |
| nanotags → Svelte | 커스텀 엘리먼트 12개 | 렌더러를 하나로 |

### 왜 틀었나

nanotags 로 폰트 메뉴를 옮기면서 계획서 §2 가 규칙 셋을 찾았습니다 — 마크업을
직접 만들어야 하고, `<template>` 은 컨테이너 밖이어야 하고, 묶음 있는
`<select>` 에는 `renderList` 가 반쪽입니다. 결론은 **"nanotags 가 준 것은
렌더링이 아니라 껍데기"** 였습니다.

남은 일이 다이얼로그 여섯이라는 것이 그때 문제가 됐습니다. 이미지 다이얼로그는
상태가 아홉 개고 서로 물려 있는데, 그걸 `paint()` 하나에 손으로 엮는 일이
남아 있었습니다. 그래서 Svelte 로 틀었습니다.

**틀길 잘했는지는 두 자리에서 눈에 보입니다.**

- 이미지 다이얼로그 — 상태 아홉을 `$state` 로 두니 381 → 291줄
- 폰트 메뉴 — 묶음 꼴 전환 때문에 컨테이너를 손으로 다시 세우던 코드
  (`containersFor` · `grouped` 변수)가 통째로 사라짐

## 2. 번들 — 예측과 실측

계획서 §5 는 "이득이 마지막에만 온다" 를 정확히 맞혔습니다. 하지만 **이득의
크기와 자리**를 틀렸습니다.

| | 이주 전 | 이주 중 최대 | 지금 |
| --- | --- | --- | --- |
| JS | 227.58 kB (gzip **71.27**) | 271.72 kB (gzip 88.38) | 228.24 kB (gzip **71.16**) |
| CSS | 60.26 kB (gzip **10.57**) | 60.26 kB | 27.17 kB (gzip **5.57**) |

**JS 는 사실상 그대로입니다.** gzip 0.11 kB 차이는 잡음입니다. Preact +
signals + kinu 가 빠진 자리에 Svelte 런타임과 컴포넌트 코드가 들어왔습니다.
계획서가 기대한 5 kB 는 `nanotags + nanostores` 로 갈아타는 경우의 계산인데,
실제로는 Svelte 로 갔고 컴포넌트 코드 자체도 조금 커졌습니다.

**CSS 가 진짜 이득이 난 자리입니다.** 계획서는 CSS 를 세지 않았습니다. kinu 의
스타일시트 48 kB 중 **실제로 쓰는 17 kB 만** 가져오면서 절반 아래로
줄었습니다 (`packages/ui/src/styles/kinu.css`).

> **이 표가 이 문서에서 가장 중요합니다.** "번들 5 kB" 를 근거로 시작한
> 이주가 그 근거에서는 거의 아무것도 못 얻었습니다. 값이 난 곳은 CSS 와
> 죽은 코드 3104줄이었고, 둘 다 계획서에 없었습니다.

### 곁들여 빠진 것

죽은 Preact 컴포넌트 24개와 훅 열. 옮긴 뒤 아무도 안 부르는 채로 남아
있었는데, 배럴이 계속 내보내고 있어서 안 보였습니다.

공개 API 도 함께 줄었습니다. 툴바 안 조각까지 스물 몇 개를 내놓다가, 앱이
조립하는 단위 다섯으로 줄었고, 앱까지 Svelte 가 되면서 **컴포넌트를 내보내지
않게 됐습니다.** 앱은 `sagak-ui/svelte/…` 로 하나씩 집습니다. `src/index.ts`
에 남은 것은 문서 저장소와 선택 영역 구독뿐입니다.

## 3. 사보타주 — 68번 중 27번이 안 물었습니다

컴포넌트를 옮길 때마다 **고친 것을 일부러 부수고 검사가 실패하는지** 봤습니다.
통과하면 그 동작에는 검사가 없다는 뜻입니다.

> 숫자는 커밋에 남긴 **표의 행**을 센 것입니다. `find-replace-dialog` 커밋은
> 본문에 "넷 중 셋" 이라고 적었는데 정작 표는 세 줄입니다 — 그때 셈이
> 틀렸고, 여기서는 기록이 남은 표를 따릅니다.

| 컴포넌트 | 사보타주 | 안 물음 |

| find-replace-dialog | 3 | 2 |
| special-character-dialog | 6 | 3 |
| list-buttons | 6 | 4 |
| export-menu | 4 | 2 |
| format-toggles | 7 | 3 |
| document-bar · dialog | 6 | 2 |
| toolbar 껍데기 | 3 | 0 |
| autocomplete-popover | 3 | 2 |
| 정렬 · 되돌리기 | 3 | 0 |
| 툴바 셀렉트 넷 | 4 | 3 |
| 경계 조회 고침 (후속) | 2 | 0 |

### 되풀이된 모양 셋

**① 여닫는 것만 보고 하는 일은 안 봤습니다.**
Export 메뉴가 가장 컸습니다 — 발행을 **통째로 삭제**해도 175개가 통과했습니다.
"열리고 항목이 셋이고 누르면 닫힌다" 까지가 검사의 전부였고, 정작 내보내기
메뉴에서 안 보던 것이 내보내기였습니다.

**② 지금 상태를 보여주는 일은 거의 안 봤습니다.**
서식 토글 넷 중 **굵게 하나만** 검사가 있었습니다. 목록 버튼의 켜짐 표시·
아이콘·고른 항목 표시 셋 다 없었고, 폰트 메뉴는 "글에 이미 걸린 글꼴을 읽어
오는 쪽" 이 비어 있었습니다.

**③ 안에서만 맞는 검사가 있었습니다.**
`링크를 삽입하고, 다시 열면 기존 URL 을 미리 채워야 함` 은 이름 그대로 그
동작을 본다고 적혀 있고 실제로 입력칸 값을 확인합니다. 그런데 그 앞에서
`https://example.com` 을 직접 쳐 넣고 **입력칸을 안 비웠습니다.** 다시 열었을
때 보이는 값은 미리 채워진 것이 아니라 방금 친 것이 남아 있던 것이라,
미리 채우기를 지워도 통과합니다.

`showModal()` 도 같은 갈래입니다. 다이얼로그를 이름으로 찾는 헬퍼가 **안
열려도 내용을 읽어 주기** 때문에, 여는 코드를 지워도 통과했습니다. 링크·
이미지·특수문자·문서 목록 넷에서 같은 구멍이 나왔고, 헬퍼에 "열렸는지" 를
넣어 한꺼번에 막았습니다.

### 못 만든 재현 셋

정직하게 남깁니다. **재현을 못 만들어 검사를 못 세운 것**들입니다.

- **선택 영역 저장·복원** — 셀렉트에 `focus()` 를 줘도 이 브라우저는 DOM
  선택을 안 지웁니다. 빼도 넣어도 결과가 같습니다
- **`mousedown` 의 `preventDefault()`** — `<li>` 는 원래 포커스를 안 받아
  `document.activeElement` 가 그대로입니다
- **목록 갈래를 바꾼 직후의 툴바 상태** — 문서는 `<ol>` 로 바뀌는데 캐럿이
  새 `<li>` 안이 아니라 편집 영역 `<div>` 에 얹힙니다. **이주 전부터**
  그랬고(Preact 판으로 되돌려 확인) 고칠 자리가 여기가 아니라 넘겼습니다

## 4. 사보타주가 찾은 **제품 결함**

27번 중 하나는 검사 구멍이 아니었습니다.

툴바 셀렉트를 옮기며 "선택 추적 구독을 지워도 아무것도 안 걸린다" 는 것이
단서였습니다. 재 보니 구독이 안 도는 것이 아니라 **조회가 틀린 값을 주고**
있었습니다.

```
<p><strong>굵은 글자만</strong></p> 를 ⌘A
  queryState('bold')        → false   ← 우리 것
  queryCommandState('bold') → true    ← 네이티브

<p><font size="5">큰 글자</font></p> 를 ⌘A
  queryValue('fontSize')      → "3"   ← 우리 것
  queryCommandValue('fontSize') → "5" ← 네이티브
```

원인은 `sagak-core` 의 `native-query` 였습니다. 조회가 "선택 시작 지점의
서식" 을 `range.startContainer` 로 잡는데, **범위가 요소 경계에서 시작하면**
컨테이너가 곧 그 요소라 조상 탐색이 내용을 건너뛰고 위로 올라갑니다.
`selectNodeContents(편집영역)` 인 ⌘A 가 정확히 그 모양입니다.

증상은 눈에 보이는 것이었습니다 — **글이 전부 굵은데 굵게 버튼이 꺼져
보이고**, 크기 메뉴가 실제와 다른 값을 가리킵니다. 캐럿·드래그로 고르면
`startContainer` 가 텍스트 노드라 원래부터 맞았고, ⌘A 만 틀렸습니다.

고치면서 하나가 더 나왔습니다. `<p><strong>글자</strong></p>` 의 `(p, 1)` —
굵은 글 **바로 뒤**에 커서를 두면 거기서 치면 굵게 이어지는데, 뒤에 자식이
없어 컨테이너로 떨어지면서 "굵지 않음" 이 됐습니다. 뒤에 아무것도 없으면
**앞의 것**을 보도록 했습니다.

> 이 결함은 **이주가 만든 것도, 이주가 건드린 것도 아닙니다.** 사보타주라는
> 방법이 찾았습니다. "검사가 안 물었다" 를 검사의 문제로만 보지 않고 한 겹
> 더 판 것이 값을 냈습니다.

## 5. 살아남은 것 — 렌더러를 안 보던 코드

렌더러를 **네 번** 갈아타는 동안 한 글자도 안 바뀐 것들입니다.

| | 무엇 |
| --- | --- |
| `subscribeToSelection` | IME 조합 중 무시 · 다음 프레임까지 지연 · 에디터 밖이면 건너뜀 |
| `icon()` | lucide 데이터로 SVG 를 만드는 함수 |
| `getCurrentAlignment` · `getSelectedLink` · `findTableAtSelection` | 선택 영역에서 사실을 읽는 순수 함수들 |
| `*.shared.ts` | 프리셋 색·폰트 목록·특수문자 목록 같은 데이터 |

**규칙으로 굳었습니다** — 컴포넌트 밖의 사실은 모듈로, 컴포넌트 생애에 묶인
것만 컴포넌트에. 폰트 목록·문서 상태·선택 영역은 모듈로 올라갔고, ⌘S 단축키·
닫기 경고·바깥 클릭·타이머는 컴포넌트에 남았습니다.

이 가름이 이주 비용을 정했습니다. 옮길 때 실제로 다시 쓴 것은 **마크업과
배선뿐**입니다.

### 반대로, 렌더러를 알던 것은 다 깨졌습니다

`render.browser.test.ts` 는 Preact 의 `options.__r` 을 가로채 렌더 횟수를
셌습니다. 서식 토글을 옮기자 셀 대상이 사라져 곧바로 깨졌고, `MutationObserver`
로 **툴바 DOM 이 실제로 얼마나 바뀌는지**를 재는 것으로 바꿨습니다.

바꾸자마자 하나 나왔습니다 — 캐럿을 열 번 움직이면 켜진 정렬 버튼에
`data-state="active"` 가 **열 번 다시 쓰였습니다.** 값이 그대로인 헛쓰기였고,
Preact 렌더 횟수로는 영영 안 보이는 종류였습니다.

같은 파일의 다른 검사는 더 조용히 망가져 있었습니다. `HistoryButton` 을
커스텀 엘리먼트로 옮긴 뒤로 **Preact 컴포넌트가 아예 없어서**
`expect(names.get('HistoryButton')).toBeUndefined()` 가 늘 통과했습니다.

## 6. 걸린 것들 (다음에 같은 일을 한다면)

| 걸린 것 | 어떻게 드러났나 |
| --- | --- |
| 아이콘 패키지의 **이름이 다름** | `IndentDecrease`→`ListIndentDecrease`, `AlignLeft`→`TextAlignStart`, `Loader2`→`LoaderCircle`. 세 번 겪고 규칙으로 인정 |
| `k` 속성을 빠뜨림 | 옮긴 컨트롤만 kinu 스타일을 못 받아 폭·테마가 갈림. 폭 검사와 테마 검사가 잡음 |
| `SvelteHost` 가 **한 틱 늦게** 마운트 | 하네스가 뼈대만 보고 돌려주다 "버튼을 찾지 못했습니다" |
| 부작용 import 를 같이 지움 | 마지막 커스텀 엘리먼트를 지우며 `editor-context.ts` import 도 지웠고, 타입만 남은 import 는 컴파일에서 사라져 **53개가 무너짐** |
| CSS 를 쉼표로 자름 | `:is(a,b)` 안쪽까지 잘려 `[k=select]{flex:1}` 이 새어 나옴. 셀렉트 폭이 60·70·85 → 전부 97px |
| 검사 내용이 깨져 있었음 | 글꼴 스택 안의 큰따옴표가 `style="…"` 를 끊어 소독기가 빈 값만 남김. **컴포넌트를 먼저 의심했음** |

마지막 줄이 이 목록에서 제일 값집니다 — 재는 도구가 틀렸을 가능성을 먼저
보는 습관이 없으면, 멀쩡한 코드를 고치게 됩니다.

## 7. 지금 상태

```
packages/ui/src/
  svelte/      컴포넌트 21개 + 셀렉트 명세
  state/       document-store · selection · local-fonts
  elements/    icon.ts 하나
  components/  *.shared.ts · *.utils.ts 만 (컴포넌트는 없습니다)
  styles/      index.css + kinu.css (가져온 17 kB)
```

검사: core **1119** · ui **186**.

`hooks/` 는 이주가 끝난 뒤에 `state/` 로 접었습니다. 실제 훅은 Preact 를
걷어낼 때 이미 다 없어졌고 구독과 저장소만 남아 있었는데, 이름 바꾸기를
이주와 같은 커밋에 섞으면 무엇이 무엇을 깨뜨렸는지 못 가립니다. 옮기는 일이
